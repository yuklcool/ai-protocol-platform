# RTU 报警及专项核查

1. 加载 `sql-safe-query`，根据当前对话的 RTU、时间、报警状态和专项问题检索案例、动态生成 SQL，通过 `sql_query_readonly` 执行。原型 payload 的 scene=rtu_alarms；未解除报警默认全部层级，不强行限定今天或固定夜间。
2. 页面自动展示报警类型、时间、源记录处理时刻、历史证据与专项缺口。历史恢复流水未经确认时，不给截止时点解除结论。报警关联巡测只代表其真实采样时点。
3. 加载本技能返回的专项参考后分析，不把不同报警套同一诊断：
   - 漏电：确认原单位和支路，核验是否大于1 A、自动断电、闭锁与动作后有效采样。≤1 A不能判安全；无动作记录不叫失败。
   - 缺相：先确认昼夜、报警相与回路映射，再核对同事件相/回路电流与关联断路报警；不能只凭0 V定因。
   - 相过流：对照前两日同一时段曲线，确认一致性标准、回路额定电流与20%边界规则。缺额定值不算比例，不把未查到回路超流当作已证实外接电。
   - 断路：先确认亮化灯/道路灯，再查连续小于3 A且频繁波动、当晚报警前稳定值的4倍、回路/总电流变化。未知灯具类型或基准时停止对应分支。
4. 服务未核实的支路、相位、单位、保护动作、历史挂载均列为缺口，不从编码串或描述中猜测。不宣称消警、复电、断电、复位或派单已执行。

专项原规则见 `references/business.md`；平台边界见 `references/runtime.md`。
