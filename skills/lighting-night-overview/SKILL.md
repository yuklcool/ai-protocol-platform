# 整夜单灯运行

1. 加载 `sql-safe-query`，根据当前对话和可信运行口径确认范围、指标及跨日窗口，检索案例后动态生成 SQL，只通过 `sql_query_readonly` 执行。用户明确到 06:00 时保留 RTU 独立 07:00 口径；不能臆定固定开关灯时间。
2. 需要原型页面时，按 `references/runtime.md` 让本次 SQL 返回 scene=night 的 `lighting-query/v1` payload，平台自动展示真实结果。不调用固定查询工具，不重复填写数值或输出 JSON/HTML。
3. 用短文回答范围、夜间有样本/纳入灯数、有效巡测区间能耗及最需关注的真实对象。将采样覆盖、在线、开灯、故障分别表达；白天不上电不直接判坏灯。没有生产在线标准时不算在线率。
4. 用户要求完整报告时，依据本次查询事实和缺口形成原九章 report，可打开“完整报告”。聊天默认短结论；没有查询依据不编造内容。章节固定名称含 07:00 时，正文仍写明本次真实截止时点。
5. 清单搜索、排序、证据抽屉和 CSV 在宿主处理。追查保留真实 lamp_id、锚点和证据窗，经安全 SQL 技能重新生成查询。当前台账不能当作历史挂载证明；无证据不展开同回路/上游影响。

细则见 `references/business.md`；所有场景通用接口和边界见 `references/runtime.md`。
