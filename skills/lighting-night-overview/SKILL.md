# 整夜单灯运行

1. 沿用上下文已明确的设备范围，默认全系统、北京时间。调用 `query_lighting(request={"scene":"night","scope":"全系统"})`。服务自动选择最近完整的 18:00–07:00；指定日期时传带 `+08:00` 的 `window.start/end`。明确到 06:00 时保留独立 RTU 18:00–07:00 窗口。
2. 服务返回后，结果自动挂入原型的 Workbench 页面，不再调用 `render_a2ui` 重新拼表，不把 JSON 贴到聊天，也不让模型提交指标或报告正文给展示工具。
3. 用短文回答范围、夜间有样本/纳入灯数、有效巡测区间能耗及最需关注的真实对象。将采样覆盖、在线、开灯、故障分别表达；白天不上电不直接判坏灯。没有生产在线标准时不算在线率。
4. 原九章报告由服务的 `report` 提供，用户可打开“完整报告”。聊天默认短结论；用户要求正文时按服务实际报告列全九章，不编造缺失内容。章节固定名称含 07:00 时，正文仍写明本次真实截止时点。
5. 清单搜索、排序、证据抽屉和 CSV 在宿主处理。查询单灯历史用返回动作或按该行 `lamp_id`、锚点、证据窗再次调用同一工具。当前台账不能当作历史挂载证明；无证据不展开同回路/上游影响。

细则见 `references/business.md`；所有场景通用接口和边界见 `references/runtime.md`。
