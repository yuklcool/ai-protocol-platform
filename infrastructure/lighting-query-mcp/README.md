# 照明六场景 Skill 与生产只读适配

本目录连接既有 `sql_query_readonly`，不直连数据库、不让模型提供自由 SQL 或 UI 事实，不修改 nanobot 源技能。六个 Skill 位于仓库 `skills/lighting-*/`。对应原型：`outputs/lighting-a2ui-2026-10-26/index.html`。

## 安装

通过平台 Skill CRUD API 导入 SKILL.md 的正文及 references，绑定 Root；复制文件本身不会生效。`deploy.py` 在目标服务器执行此步骤，先备份平台配置和同名 Skill，再配置独立只读 MCP、限定当前管理员账号，最后绑定六技能并启用已有 A2UI 动作开关。保留原模型、既有工具权限与其他 Skill。

运行镜像需包含本分支的账号范围校验。GitHub 工作流测试通过后构建专用镜像，部署脚本必须先确认当前后端支持 `allowedUserIds`。连接凭据从平台已有配置读取，保存到服务器的 `private/connection.json`（0600），不写入 Git、Skill 或日志。适配容器只加入平台内部网络，不发布端口，MCP 额外校验独立令牌。

## 业务边界

- 夜间默认最近完整18:00–07:00，单灯06:00请求保留RTU独立07:00窗口。当前夜间值是单灯巡测累计值的观测区间差，尚未取得RTU完整夜间能耗，必须标明；不能拿自然日D日报冒充夜间。
- 日报按字符型 `read_date_time` 的ISO日期前缀过滤，只用D。RTU逐条[0,1500)，单灯逐条[0,100)；重复日报留空。30日上升同时≥50 kWh且≥30%，必须相邻自然日，前日零不算比率。
- 节能率复用原技能 `seven_day_analysis.py` 的固定取数对象和字段；不同于脚本的百分比展示，返回原始比率供已有宿主格式化。先合计有效配对能耗，缺目标不判达标。
- 报警保留当前处理信息。没有可信事件流水映射，不宣称完整历史恢复或独立事件数，不从末态倒推截止时点，也不把无可靠未解除分类隐藏成空列表。
- 对账使用单灯→回路→回路开关→控制箱→RTU主链路，当前台账只给核查线索。未证实历史归属时，已验证差额、比值和倒挂结论为空，不开放跨层级查询。
- RTU在线判定配置、专项相位/支路映射、原始漏电单位和保护动作仍需可信证据；页面明确列缺口。不引入演示10分钟阈值，不按比例编造分项，不执行设备控制。
- SQL端单条SELECT/WITH、安全入口、90秒超时、2并发；明细默认200最多500，独立范围聚合，失败不显示零。

这些限制表示生产证据未齐，六个技能可调用与原型所有诊断路径完全验收是不同状态。不要据此关闭 #152。

## 验证

本地只编辑。`.github/workflows/lighting-skill-adapter.yml` 在GitHub托管Runner用一次性PostgreSQL验证真实SQL、全部六场景/四能耗视图、截断、累计读数复位、重复日报、自然日配对、零/空值、主链路、契约、令牌和Skill包；常规CI验证后台授权与前端回归。完整链路通过真实HTTP连接有状态SQL MCP与照明MCP，覆盖SQL工具的结构化封装和文本JSON返回。照明工具显式声明`LightingResult`，返回结构化`lighting-query/v1`并保留SDK输出校验。

SQL执行失败、截断、缺少完整性标记及畸形返回均作为失败处理，不转换为空结果。日志仅记录参考号和固定失败类别；嵌套transport异常展开到类型，避免只留下`ExceptionGroup`，不记录异常原文、SQL、业务行或凭据。

服务器联调应通过手动GitHub工作流和临时自托管Runner执行。Runner只接受已审核的本任务提交，验收结束后注销清理，不向PR暴露生产凭据，日志只保留计数、状态及调用链。原型合成数据不得替代生产返回。
