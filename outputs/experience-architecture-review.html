问题本质 01

概念没有收敛

产品已经只有一个助手，但 Skill 仍同时像入口、助手和可编辑资源。用户在协议概念之间穿行，而不是围绕一个目标前进。

问题本质 02

状态没有贯通

创建、测试、绑定、权限、当前可执行是不同事实；分散页面的成功提示，不能证明目标用户真的可用。

问题本质 03

任务没有闭环

“工作台”自动跳最近会话，历史藏在聊天侧栏，成果主要依附会话；缺少稳定的开始、找回和继续位置。

01 / 以源码为证据

先修断点，不先增加功能

以下 10 项描述源码事实；“影响”是待业务运行和用户研究确认的判断。P0 指建议优先处理的正确性断点，不代表已确认生产事故。

P0D01 · 相同“登录”按钮，行为不一致

事实：导航账号区直接调用 signIn()；local-jwt 适配器该方法抛错，而独立登录组件另行处理密码登录。

影响：同一产品入口可能出现一个能登录、另一个失败且无就地反馈。

设计：统一认证入口及错误反馈；登录后返回原任务。保存安全的站内返回目标，不重复提交用户操作。

[E01] UserMenu.tsx:53–61；AuthContext.tsx:243–255。运行复现：未执行。
P0D02 · 新建 Skill 后仍停留在 new 身份

事实：isNew 由路由决定，保存成功仅更新 draft，没有切换到返回的实体 ID；后续保存仍选择 POST。

影响：再次编辑保存存在重复创建风险；后端 POST 对 slug 冲突会自动加后缀，不能依靠名称冲突阻止重复创建。

设计：首次创建成功立即替换为实体路由；后续更新走同一实体。提交防重复、失败保留内容；保存内容与“启用给助手”分别确认。

[E02] app/skills/studio/[skillId]/page.tsx:70,109–143。
P0D03 · 个人能力列表与保存规则不一致

事实：前端使用 owner_id 参数，后端列表声明别名为 ownerId；保存个人绑定要求资源必须本人拥有。

影响：候选列表存在混入共享但非本人能力的风险，出现“看得到、选得上、保存被拒”。

设计：候选与提交复用相同资格规则。本人拥有的 Skill 才显示“为我启用”；公共能力显示管理员配置结果，而不是让用户越权绑定。

[E03] PersonalProfileEditor.tsx:19–21；backend/skills/routes.py:269–286；backend/db/user_profiles.py:24–35。
P0D04 · “用于 Root”的模型验收口径不统一

事实：专用 use 接口检查当前配置 24 小时内普通生成和工具调用双测试；Root 保存走通用配置接口，该入口未见同等检查。current 接口的 allowed 是解析与区域策略判断，不是双测试结果。

影响：不同入口对“可用于对话”的承诺不一致。此处不是断言运行时没有其他校验。

设计：数据库动态模型保留已有双测试验收策略，统一所有修改该类模型的入口；配置文件模型保留现有部署管理方式，不擅自套用数据库专用接口。分别展示“策略允许、最近测试、已选用、当前运行结果”。测试记录过期只使验收证据待更新，不在本设计中擅自新增运行时停服规则。

[E04] backend/admin/model_probe_routes.py:208–265；platform_config_routes.py:84–116；backend/config/platform_config.py:132–141；RootAgentSettingsPage.tsx:166–179。
P1D05 · 工作台不是稳定目的地

事实：侧栏“工作台”指向 /，首页自动跳最近会话；读取失败时可能回到宣传页。

设计：登录后默认进入稳定工作台；最近任务作为“继续”卡片，不强制跳走。后端错误在工作区内显示故障和重试，不伪装成未登录或未配置。

[E05] ConsoleSidebar.tsx:44–50；HomeGate.tsx:27–39；useLandingTarget.ts:44–64。
P1D06 · 一种 Skill，多个产品身份

事实：市场 Skill 进入专属路径，技能管理卡片进入编辑器；实际聊天统一使用 agentId="root-agent" 并传能力提示。

设计：将 Skill 呈现为“助手的能力”，不是第二个助手。列表默认解释能力与可用条件；明确分开“用它完成任务”和“编辑我的技能”。旧链接保留兼容。

[E06] MarketplaceSkillsSection.tsx:37–45；app/skills/page.tsx:89–102；app/chat/[...path]/page.tsx:71–82。
P1D07 · 历史恢复规则和错误状态不一致

事实：历史列表跨 Skill，选中时只传 session_id 并保留当前路径；首页则依历史 skill 信息拼接。hook 提供 error，但 ChatShell 未传递给历史面板，空列表分支可能把首次加载错误呈现为空历史。

设计：统一按会话身份解析路由和上下文；历史成为全局可见入口。加载、确实为空、读取失败、不可访问分开显示；不通过错误消息泄露私有会话存在性。

[E07] ChatShell.tsx:1145–1182；SkillSessionPanel.tsx:95–125；useSkillSessions.ts:63–102。
P1D08 · 附件子流程阻塞整块输入

事实：附件初始化、上传、保存、解析状态进入统一 attachmentBlock，同时禁用 textarea 与发送。

设计：允许继续编辑草稿；仅阻塞依赖尚不可读附件的提交。纯文本降级必须显式确认“本轮不使用附件”，服务端确认上下文为空后才发送；无法确认时维持阻塞，不能静默漏文件。

[E08] ChatShell.tsx:1251–1259,1533–1535,1581–1584,1621–1632。
P1D09 · 创建 / 检测成功，没有完成启用闭环

事实：Skill 保存不等于公共或个人绑定；MCP 诊断不等于启用与 Root 绑定；知识创建仅更新本地 selected，还需保存 Root。知识页面已有相应提示，并非完全没有反馈。

设计：每个资源都显示“已保存、验证状态、应用范围、对我是否有效”，给出唯一下一步；有权限者完成绑定，无权限者只查看说明，不制造不存在的审批流程。

[E09] KnowledgePanel.tsx:72–86,310–333；backend/auth/capability_access.py:27–66；backend/admin/mcp_servers_routes.py:145–176。
P1D10 · 编辑上下文缺少跨页接续

事实：Root 栏目与配置为组件状态，跳技能页未携带返回栏目；Studio 取消有脏数据确认，但顶部资源链接直接离开。另有导入失败仅输出日志的路径。

设计：统一离开保护、带任务来源的返回位置、保存失败恢复；导入失败必须在触发点显示重试，不只记录日志。

[E10] RootAgentSettingsPage.tsx:77–89,273–279；SkillStudioShell.tsx:21–26；ChatShell.tsx:1461–1483。
不重建：稳定 thread ID、附件选择持久化、上传取消与重试、A2UI 产物恢复、模型双测试与配置指纹、资源 ACL 和 effective-access 已有基础。优先把它们接成用户能理解的闭环。

02 / 目标体验架构

两条闭环，四个核心对象

用户面对任务，管理员面对可用性。协议和资源类型留在能力配置内部，不成为所有人的导航骨架。

日常用户：开始 → 执行 → 成果 → 继续

开始 / 恢复

输入目标，选最近任务
不先选模型或协议

执行 / 补充

对话、附件、交互表单
同一会话承接上下文

查看成果

结果可预览、可追溯
失败不冒充成功

继续完善

回原任务，补充要求
新任务需明确确认

管理员：接入 → 验证 → 启用 → 用户验收

接入资源

模型、MCP、技能、知识
只填写当前所需信息

验证能力

按资源类型执行检查
说明时间与配置版本

明确启用

公共 / 仅本人不混淆
预览本次影响范围

目标用户验收

权限诊断 + 实际操作
管理员成功不是全员可用

对象 01

会话 = 任务容器

保留 Session/thread 身份；“任务”先是体验层的称呼，不新建另一套项目、任务引擎或 Agent。

对象 02

运行 = 一次执行

一次发送或表单操作对应运行状态；完成、停止、失败分别展示，不把完成回复等同业务执行成功。

对象 03

成果 = 可回到的结果

复用 Artifact / A2UI / 文档；区分可下载文件、可恢复交互表面与纯文本回复，不虚构文件。

对象 04

能力 = 授权资源组合

Skill 是内容能力；工具、MCP、知识由 Root 按权限提供。选择能力不突破平台能力上限。

01 · 意图入口层

稳定工作台 / 最近对话 / 找成果 / 能力发现；先回答“我能做什么、从哪里继续”。

02 · 任务现场层

对话 + 附件上下文 + 运行反馈 + 成果工作区；移动端按对话 / 成果切换，不把用户推出任务。

03 · 体验编排层

统一认证、就绪摘要、下一步动作、跨页返回、草稿保护与局部故障；不复制权限判断。

04 · 能力运行层

复用 Root Agent、AG-UI、A2UI、MCP Apps、Session、Artifact 和现有资源接口。

贯穿所有层

服务端授权与用户隔离、状态一致性、可恢复性、键盘及读屏可用性、必要操作审计。

03 / 信息架构与角色

使用与管理分区，发现与编辑分开

以下为目标结构，不是当前已有导航。角色按现有普通用户 / 平台管理员划分；“技能作者”是用户行为模式，不新增权限角色。

所有已登录用户

日常工作区

  • 工作台：新建任务输入、最近任务、近期成果；只显示与我相关的可用性提醒。
  • 历史对话：按标题与时间找回，删除仍沿用所有者权限。
  • 我的成果：按任务、类型、时间查找；每项都能回原对话。
  • 能力中心：可用能力 / 我的技能；先发现、使用，再按需编辑。

个人信息与偏好留在账号菜单；技能绑定操作从能力中心进入，同一数据源，不维护两套开关。

仅平台管理员

平台管理区

  • 就绪总览：初始化清单、阻塞原因、下一步与目标用户验证。
  • 助手配置：保留 Root 单一配置主体，基础设置与高级协议渐进展开。
  • 资源接入：模型 / MCP / 知识 / 公共技能，统一生命周期视图。
  • 运营与治理：用户 / 用量 / 审计 / 平台设置。

管理区有固定“返回工作区”；隐藏入口不等于授权，所有接口仍执行服务端校验。

目标入口路由建议旧入口与迁移规则
公开入口 / 登录回跳/ 保留公开介绍；登录默认到 /workspace（新增）有明确站内深链时优先返回深链；无深链才到工作台，不自动进入最近任务。
任务现场保留 /chat/root-agent?session=…旧 Skill 聊天链接按授权解析成能力提示，保留会话；切换路径不得自动重发旧指令。
历史 / 成果/sessions / /results（新增）先做现有 Session / Artifact 的索引视图；没有后端聚合能力时先提供“从会话找成果”，不显示假列表。
能力中心 / 我的技能改造 /skills；保留 /skills/studio/:id默认使用视角；拥有者显式进入编辑。Studio 受部署开关影响，关闭时不展示不可执行创建入口。
个人设置保留 /settings/personal偏好与个人信息为主；技能绑定展示摘要并链接回能力中心，仍写原 profile 数据。
管理就绪 / 助手配置改造 /admin；保留 /agent模型、MCP 等现有路由保留；配置栏目可深链，任务来源通过受校验的站内返回信息接续。
不做的重构：不恢复独立多 Agent 编辑，不引入组织、审批中心、项目空间，不把 MCP Apps 移出独立源，不为做成果入口而把私有文件改成公开链接。

04 / 关键旅程

每条路径都有成功出口，也有失败出口

切换旅程查看目标流程。理想路径不是强制向导：平台已就绪时，普通用户无需先完成任何配置。

首次使用 · 先让用户完成一件小事

统一登录，回到原意图

保留站内深链与未提交输入；用户切换身份时清理前一账号的上下文。

工作台只有一个主动作：开始任务

示例是可编辑提示词，不自动发送；无示例也能直接输入目标。

进入同一个任务现场

建立稳定会话身份；显示实际使用的文件与可用能力，不要求用户选 Root / Skill / 协议。

结果落在当前会话，并提供下一步

正文可复制，文件可预览 / 下载，交互表面保留动作状态；“继续完善”使用原会话。

平台未配置模型：普通用户看到“助手暂未可用，需平台管理员完成配置”，不引导去无权页面；管理员看到具体缺口与修复动作。网络错误与未配置必须分开。

找回与继续 · 从任务或成果都能返回上下文

工作台“继续”或历史搜索找到任务

显示标题、最近活动、是否有成果；不要求记住 Skill 或文件名。

按会话身份一次解析恢复

恢复消息、附件选择、产物与运行记录；URL、欢迎内容和能力提示由同一解析规则决定。

从“我的成果”进入结果

保留来源任务链接。普通文件可直接预览；交互表面必须在原授权与沙箱约束内恢复，不能重新执行工具。

在原任务补充要求

只有用户显式选择“作为新任务”时新建会话；复用哪些附件要可见且重新授权。

找不到或无权查看：提供返回历史与新任务，不泄露私有资源。部分内容恢复失败：显示已恢复部分和重试范围，不将整段对话清空。

附件异常 · 阻塞依赖，不阻塞思考

上传、解析、选入上下文分别显示

“上传完成”不能写成“可分析”；草稿输入始终可继续编辑。

失败文件就地说明原因

给出重试解析、取消选入、替换文件；不让用户重复上传所有成功文件。

提交前校验本轮上下文

有不可读且选中的附件就阻止依赖文件的提交；不得声称分析成功。

显式选择“本轮仅发送文字”

清晰告知不分析附件；服务端确认 documentIds 为空再发送。上下文无法确认时不允许降级。

该降级策略是待实现设计，必须验证现有发送接口是否支持安全覆盖上下文；不能只在前端解除 disabled 就算完成。

个人技能 · 保存内容与启用分清，接续不分散

能力中心 → 我的技能 → 新建

仅在 Studio 已启用时显示新建；公共能力默认展示使用方法，不默认进入编辑器。

保存内容，立即进入新实体路由

明确“已保存，尚未为我启用”；保留实体身份和返回位置，不再重复 POST。

一键“为我启用”，显式写入 profile

仅允许本人拥有的 Skill，复用现有个人绑定校验；公共启用由平台管理员处理，绑定不改变 ACL。

到同一助手尝试一个示例任务

显式发起新任务，提示词先填入不自动执行；展示实际是否加载能力，而不是“点击即成功”。

保存成功但启用失败：保持“内容已保存 / 启用失败”，单独重试绑定；不回滚或重复创建内容，不假装两次写入是一个原子事务。

管理员初始化 · 先打通最小可用路径

就绪总览定位必要缺口

最小路径只有身份 / 服务、Root 模型与策略、真实对话；MCP、知识、Skill 是按需扩展，不成为全员聊天的前置条件。

接入模型，处理部署侧凭证引用

说明“变量名不是密钥”；需要修改后端环境时保留向导进度，返回后重新检查，不承诺纯网页能完成部署。

普通生成 + 工具调用测试，再确认用于助手

复用既有测试有效期和配置指纹；数据库动态模型在 Root 下拉、模型页等变更入口使用同一验收规则；配置文件模型仍走部署侧流程。

以目标普通账号完成一次真实任务

管理员权限诊断不冒充用户登录或授权。无安全代验接口时让目标用户登录验证；通过后才记录该范围可用。

就绪检查分“配置检查、最近验证、当前请求”三层；无法获取时显示未知和重试，不显示绿色就绪。

扩展连接 · 检测只是中间站

登记 MCP 连接和服务端凭证引用

显示保存与启用开关的影响；敏感凭证不出现在设计产物、客户端缓存或诊断日志。

健康检查与能力发现

显示具体工具和权限范围；只读取检测不自动启用。

显式“启用并绑定到助手”

先预览影响范围，再按现有接口分步写入；部分失败时显示哪一步成功、哪一步待重试。

验证目标账号的有效权限，再进行安全真实调用

复用服务端授权；有副作用的工具先确认，不以重新检测为由重复执行。MCP Apps 保持独立源沙箱。

撤销绑定后，旧会话操作也按最新权限重新检查。旧结果仍需原资源授权；可看历史结果不代表可再次调用。

06 / 状态、反馈与连续性

不再用一个绿色标签，替代四个不同事实

能力就绪不是一条只进不退的流水线。保存、测试、应用、权限是独立维度，任一条件变化都可能使旧结论失效。

内容状态

未保存 / 正在保存 / 已保存 / 保存失败。成功以服务端回读为准，记录配置版本。

验证证据

未验证 / 验证中 / 通过 / 失败 / 过期 / 未知。展示检查类型、时间、配置指纹；不同资源按需检查。

应用范围

未绑定 / 仅本人 / 公共绑定 / 已停用。只对有资格者显示变更动作，私有共享不自动扩大。

当前有效性

对当前用户可用 / 受限 / 暂不可用 / 未知。由真实身份、当前策略与资源状态计算。

例：“已保存 · 检测通过 · 未绑定” → 下一步是“确认绑定”；“公共已绑定 · 当前用户不可访问” → 由有权限的管理员检查范围，不显示“已为所有人启用”。绑定完成也不能承诺下一次网络调用必然成功。
情境用户看到什么允许的下一步必须守住的边界
运行等待 / 执行中实际阶段与正在执行的动作，不编造百分比。继续写下一条草稿；停止当前运行。流结束不自动当业务成功；停止不承诺撤销已完成的外部副作用。
等待表单 / 用户确认“等待你确认”及具体字段。返回待处理交互，显式提交。防重复提交；已处理表单恢复后不可再次触发同一副作用。
运行失败 / 已停止保留输入、已完成步骤与部分结果。重试安全步骤；高风险操作先核对实际执行状态。不得默认重发整轮工具调用；重试与新建运行需可追踪。
真正为空 / 搜索无结果首次使用引导 / 清除筛选提示。开始任务 / 清除筛选。请求失败不能呈现为“没有数据”。
读取失败 / 断网就地错误、影响范围、最近可读内容是否可能过期。重试该区块；保留当前草稿。旧权限缓存不为受保护操作放行；不回宣传页掩盖错误。
附件解析失败文件级错误，明确尚不可分析。重试、取消选入，或显式本轮纯文字。无法确认本轮文件上下文时仍禁止提交，不让模型假装读到文件。
403 / 404 / 登录过期资源不可访问，或请重新登录。回列表、登录后回原任务。不泄露私有资源存在性；重新登录不自动重做写操作。
内容保存成功、启用失败分别列出两步结果。仅重试启用 / 查看已保存内容。不重复创建，不把多次请求伪装成原子事务。

跨页连续性契约

  • 上下文以真实用户 + Session 为根，运行与成果明确关联到来源任务。
  • 新任务重置活动运行、附件选择与能力提示；不清除已有任务数据。
  • 恢复任务不得自动重放工具；只恢复消息、状态与授权可见的结果。
  • 配置栏目可深链，离开 dirty 表单时统一提示保存 / 放弃 / 留下。
  • 返回位置仅允许站内白名单；不接受任意 URL，避免开放重定向。
  • 草稿不得写入公开 URL；涉及私有内容与密钥时不得直接落 localStorage。持久草稿需采用已授权存储并按用户隔离。

信息与交互契约

  • 普通用户主语是“助手 / 能力 / 任务 / 成果”；Root、MCP、A2UI 等留在管理、诊断和技术详情。
  • 每个阻塞提示说明：发生什么、影响什么、谁能处理、接下来做什么。
  • 每个成功提示说明：保存了什么、作用范围、是否已生效；不使用笼统“配置成功”。
  • 桌面聊天与成果并排；手机切换视图保留会话和输入，返回焦点到触发按钮。
  • 键盘可操作、焦点可见、控件至少 44px；错误用 alert、加载用 status，不只依赖颜色。
  • 继承 DESIGN.md 和 globals.css，不再引入第二套主题或组件体系。

界面收敛，服务能力复用

编排的是现有能力，不是把业务逻辑搬到前端。新索引和聚合服务都属于待评估、待实现范围。

用户动作前台触点后台职责 / 复用故障后的接续

建议增加的薄层

  1. 体验上下文：聚合当前用户可见能力、受限原因、下一步动作；禁止返回密钥及他人资源摘要。
  2. 统一会话解析器：首页、历史、深链复用同一恢复规则；历史 Skill 只保留兼容提示，不恢复独立 Agent。
  3. 成果索引投影：来源任务、类型、标题、创建时间和资源引用；不复制敏感正文，不默认保证交互表面可导出。

  • 跨页绑定是否能在现有 API 上显式分步完成；不假定可一键事务回滚。
  • 就绪摘要按用户和配置版本失效；权限最终以实时服务端检查为准。
  • 不改变已有费用估算单位；本次不重做预算、组织或模型计费架构。

08 / 改造顺序与验收

先把正确性打通，再把认知负担降下来

不一口气推倒重做。以下按依赖排序，无工期承诺；每批只验证改动范围及直接受影响链路。

阶段 A · 正确性补洞

先解决“点了不对、保存不对、口径不对”

D01–D04 优先：统一登录；新建转实体；个人候选资格一致；统一模型应用验收。同步补齐历史错误态与静默导入反馈。

交付门槛：第二次保存只更新同一 ID；不可绑定资源不出现在可选项；所有数据库动态模型变更入口执行同一验收；local-jwt 等现有认证模式都有可用登录入口。

阶段 B · 稳定入口与会话连续性

工作台、历史、同一任务现场

新增稳定工作台与历史入口；统一会话解析、返回和 dirty 保护；附件先允许编辑草稿，安全降级经接口验证后再启用。原路由保持兼容。

交付门槛：点击工作台不强制跳会话；登录深链、历史和刷新恢复一致；不自动重放旧工具；附件错误不丢文字。

阶段 C · 能力与配置闭环

从“资源列表”变成“可用能力”

能力中心分使用 / 创作；个人启用不再跨页找开关；管理员就绪总览连接接入、验证、绑定和目标用户验收。建立统一状态摘要。

交付门槛：每个未就绪状态有可执行下一步；绑定成功不伪称 ACL 已放开；多次写入部分失败可恢复且不重复创建。

阶段 D · 成果索引与体验校准

把一次回答，变成可持续工作

先核实元数据，再增加我的成果；结果可回原会话。进行普通用户 / 技能作者 / 管理员三类可用性观察；校准导航命名和能力解释。

交付门槛：成果有来源且按 ACL 读取；无法导出的表面只提供合法恢复路径；键盘、手机、错误与拒绝流程可完成。

首轮必须通过的端到端验收

  • 新用户登录 → 输入目标 → 得到真实结果，不接触协议配置。
  • 深链登录 → 回原会话 → 刷新，消息 / 附件选择 / 产物一致。
  • 历史请求 500 显示错误与重试，不显示“暂无历史”。
  • 解析失败后草稿仍可编辑；未排除的不可读附件不能提交分析。
  • 创建技能 → 再次编辑保存，仅一个实体；启用失败不重复创建。
  • 数据库动态模型的过期或变化后失效的测试证据，在该类模型各变更入口一致处理。
  • MCP 只检测时不自动启用；绑定后目标用户实际验证。
  • 知识默认私有不被“公共绑定”扩权；A/B 用户拒绝符合预期。
  • 从成果回原会话不重新执行工具；已提交 A2UI 不重复操作。
  • 退出 / 换账号清除前用户上下文；手机与键盘完成上述主路径。

埋点与衡量：先建基线，再承诺改善

指标 / 建议事件定义验收与解释
首次价值完成率
task_started → result_viewed		有开始任务行为的新用户中，得到并查看有效回复 / 结果的人数比例；排除空响应与异常结束。当前无实测基线；首轮可用性研究建议 ≥80% 参与者独立完成，属于待确认目标。
恢复成功率
session_resume_requested → restored		恢复请求后，消息及应恢复的附件 / 成果均可读取；记录部分成功，不混入完全成功。固定验收用例需全部通过；生产阈值待真实数据确定。
配置闭环率
resource_saved → capability_effective		按操作者与授权范围统计保存后完成验证、应用和目标用户验收的比例。按资源类型分开；检测通过不能直接作为 effective 事件。
可恢复故障率
blocked → recovery_action → success		阻塞状态是否展示动作，以及用户执行后能否继续；区分本人可修复和需管理员处理。所有验收阻塞态必须有出口；业务恢复率先观察再设阈值。
找回成果的路径成本
results_opened → origin_task_opened		从成果卡片返回原任务所需明确操作数，不包含认证和首次查找。目标为一个“回原对话”动作；不将页面跳转数量冒充用户满意度。

埋点只记录事件、耗时、错误类别和必要匿名关联标识；不采集提示词正文、文件内容、凭证或私有结果。停留时间不等于推理耗时，真实模型性能需单独测量。

建议本轮确认的设计方向

  1. 登录后稳定工作台，不再自动跳最近会话；最近会话保留一键继续。
  2. Skill 改为能力视角，使用与编辑分开，保留单一助手与现有权限边界。
  3. 先阶段 A，再阶段 B：先修正确性与连续性，再做能力中心和成果索引。

待用户研究确认：实际主要用户是普通使用者还是平台搭建者、最常做的 3 类任务、最常卡住的具体步骤。以上不假定已有访谈结论；反馈将用于调整导航权重，而不是阻止先修已知断点。
