# Issue #141 · 全站原型视觉评审与优化

日期：2026-10-22。基线：PR #142 的 `c6862a2`，主分支已同步至 `f46a998`。

本次修改原有 `full-platform-prototype.html`，保留 18 个页面、普通用户 / 管理员视角及对话内交互。交付是设计原型，未接入生产页面或真实服务。

## 评审结论

v2 已表达「对话内完成任务」的方向，但视觉完成度还停留在流程线框图。缺少精细感的主要原因不是装饰不足，而是层级、内容密度、模块差异和交互状态没有共同的设计尺度。

| 问题 | 对使用者的影响 | 本轮处理 |
| --- | --- | --- |
| 大部分页面由同类白色圆角卡片拼成 | 无法一眼区分输入、内容、预览和配置 | 导航为轻透外壳，内容为实色；按任务使用列表、文档封面、编辑器、诊断时间线 |
| 字体、英文标签、状态文字普遍细小且偏淡 | 关键操作不突出，中文长文扫描困难 | 标题 / 正文 / 辅助 / 数据四级尺度，提高次正文对比度 |
| Unicode 字形充当图标，粗细与基线不同 | 像临时拼接的后台模板 | 使用项目已有 Lucide 的内嵌 SVG 图标；无需 CDN 或新依赖 |
| 蓝青渐变同时用于导航、按钮、背景与卡头 | 各层权重接近，缺乏精确的视觉焦点 | 银白与石墨色承担结构，蓝色集中表达主操作、选中与焦点 |
| 完成的计划仍占用很长的垂直空间 | 待确认的表单与成果被推到首屏之外 | 完成步骤收为横向摘要；审批、结果在原消息内继续呈现 |
| 输入框在整页流中粘底，覆盖审批内容 | 操作按钮被遮挡，滚动位置不稳定 | 聊天采用独立滚动消息区，输入区是明确的布局行 |
| 成果卡只给标题，没有真实的内容形态 | 难以判断成果内容与用途 | 文档缩略预览、来源、类型、状态与返回会话入口并列 |
| 模型 / MCP / Agent 的表单长得几乎相同 | 看不出配置与验证之间的关系 | 服务配置、验证清单、能力绑定、有效状态分别组织 |
| 技术实现说明反复出现在普通用户主流程 | 挤占内容空间，读起来像接口文档 | 全局保留「交互原型 / 示例数据」说明，协议细节放在按需展开区及文档 |
| 弹窗、移动导航仅有外观 | 键盘用户难以完成流程 | 可见焦点、Escape、焦点约束与返回、移动遮罩及语义标签 |
| 表单重绘会丢失未提交输入 | 切换状态或执行演示时造成操作中断 | 保留当前编辑值，保存及测试状态明确区分 |

## 参考与取舍

- [Apple HIG · Materials](https://developer.apple.com/design/human-interface-guidelines/materials)：借鉴导航 / 控件与内容层的区分，玻璃效果只用于外壳和浮层。
- [Apple HIG · Layout](https://developer.apple.com/design/human-interface-guidelines/layout)：借鉴一致对齐、内容分组、可调整的空间布局和清晰的主操作。
- [awesome-design-md · Apple](https://github.com/VoltAgent/awesome-design-md/blob/main/design-md/apple/DESIGN.md)：借鉴银白背景、石墨文字、单一操作蓝及留白。该分析主要针对营销页面，因此不照搬大标题、巨幅图片和低密度导航。
- [awesome-design-md · Linear](https://github.com/VoltAgent/awesome-design-md/blob/main/design-md/linear.app/DESIGN.md)：借鉴细边界、精确间距、紧凑状态和数据对齐；保持本项目明亮浅色的方向。

这里的「科技感」由可理解的执行状态、清晰的数据结构和精确控件表达。用户的任务与成果是主角。

## 本轮原型设计系统

| 角色 | 定义 |
| --- | --- |
| 画布 | `#F5F5F7`，微冷银白 |
| 内容 | `#FFFFFF`，表单、文档、列表实色表面 |
| 主要文字 | `#1D1D1F`，石墨黑 |
| 次要文字 | `#626671`，保证中文说明可读 |
| 操作 | `#0066CC`，主按钮、选中、焦点 |
| 边界 | `#E3E5E9`，轻量分组和表格分隔 |

成功 / 待处理 / 失败使用单独的语义色并配文字。数字采用等宽或 tabular-nums，不以颜色单独表达状态。

标题使用系统 Display 字体栈，正文使用系统 Text 字体栈，Windows 分别使用 Segoe UI Variable / Segoe UI 与微软雅黑，macOS 使用系统 SF / 苹方；数据使用 SFMono / Cascadia / Consolas。不下载或分发 Apple 字体。18 个页面共享同一套 token，不新增独立产品主题。本轮刻意保持浅色，不引入暗色切换。

布局采用 4px 基数；控件 / 内容 / 大面板使用有区别的圆角。桌面侧栏 240px，聊天内容限制阅读宽度，宽屏列表和表格可利用更多空间。常用操作至少 44px；手机保留底部输入区并考虑 safe-area。
