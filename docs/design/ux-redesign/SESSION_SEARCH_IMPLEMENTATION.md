# #141 第二批：服务端会话搜索

本批以 main 为基线独立提交，和 #143 的消息流改版没有代码依赖。不关闭整个 Epic。

## 用户路径

历史会话 → 输入标题或会话编号、可选更新时间起止 → 搜索 → 按真实更新时间倒序分页 → 回到原会话。检索当前用户全部未归档、非预创建会话，包含首屏尚未加载的较早记录；空标题仍可按会话编号查找。只读取索引元数据，不扫描聊天文本、调用模型或恢复任务执行。

搜索表单按提交生效；重置清除已应用条件。日期按浏览器本地整天转换为带时区的边界，结束日期包含当天。切换条件立即隐藏旧结果，取消旧请求并清空游标；迟到响应不能污染新条件。翻页失败保留本页与游标，允许只重试读取。UID 切换由现有 WorkspaceGate 重建页面。

## API 与数据契约

新增认证 `GET /api/sessions/search`，保留原 `/api/sessions`、按 Skill / 文档列表及旧会话深链接。

| 参数 | 语义 |
| --- | --- |
| `q` | 最多 200 字符，去除首尾空格，不区分大小写的标题 / 会话编号字面子串；`%`、`_`、引号无通配或 SQL 含义 |
| `skill_id` | 可选精确能力标识；不以动态显示名做分页后过滤 |
| `updated_after` / `updated_before` | 带时区时间；开始包含、结束不包含；均作用于真实 lastMessageAt |
| `page_size` | 1–50，默认 20 |
| `cursor` | 版本、搜索范围摘要、最后时间和编号组成的不透明 keyset 游标 |

响应延用 sessions / next_cursor。游标绑定可信 UID、关键词、能力及时间条件，改变范围或无效游标返回 400，不静默跳回第一页；无时区时间等格式错误返回 422。时间相同时按会话编号倒序消除分页歧义，锚点被删除后仍可继续。翻页期间更新的会话可能移到较新位置，刷新从第一页重新读取；不承诺数据库快照分页。

游标不是授权令牌：每页仍校验可信资源用户，并在查询中绑定当前 ownerUid。没有按“进行中 / 已失败”等业务状态筛选，因为当前没有持久 Task/Run 状态；不从工具历史推测。

## 存储与权限

- PostgreSQL：通过新增 Repository 方法把 owner、关键词、时间、稳定排序和 LIMIT 放入参数化 SQL。owner JSONB containment 可复用基线 GIN 索引；不会将整个 collection 或其他用户会话读回 Python 再筛选。无需新增字段、迁移或全文扩展；子串匹配仍需扫描当前用户候选元数据，大规模检索索引是后续性能扩展。
- Memory：同语义回归与本地模式。
- Firestore：先以 ownerUid 服务端过滤，再在应用服务端进行子串、时间和分页匹配。Firestore 原生没有任意子串查询；这是当前用户元数据扫描，不冒充云端全文索引或数据库原生 LIMIT 性能。
- 列表只覆盖自己的会话，不扩大已有显式共享资源的读取权限，也不改变聊天、附件、成果、Memory 的授权策略。

## 验收与回滚

单测覆盖跨用户、游标范围、同时间分页、删除锚点、超过旧首屏上限的较早匹配、预创建/归档过滤、日期时区、特殊字符、空/错状态和迟到请求。真实 PostgreSQL 作业验证参数化查询与重建 Repository 后继续分页；浏览器用真实 JWT / API / PostgreSQL 与合成索引记录，覆盖 1440/768/390 和回到原会话的 URL。该场景不调用 Provider，不替代 #143 或 Epic 的真实模型与 A2UI 联调。

回滚撤回本批 API、Repository 方法和前端表单提交即可，无数据库结构或客户数据变化。保留旧列表端点和路由，已有客户端不依赖新游标。完整 CI、截图与结果记录在本批 PR。
