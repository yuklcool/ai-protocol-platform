# 对话附件上传与分析

本文对应 #119 的源码整改，部署时需使用包含该修改的构建。`v1.1.1` 发布镜像不包含后续分支上的修改。

## 配置流程

1. 按[完整配置流程](configuration-guide.md)部署、登录并创建账号所属租户。在 Root Agent 中选好模型，先通过普通生成和工具调用探测。
2. 默认自托管使用 PostgreSQL 和本地文件卷。确认 `DATA_BACKEND=postgres`、`SESSION_BACKEND=postgres`、`OBJECT_STORAGE_BACKEND=local`，以及 `OBJECT_STORAGE_LOCAL_ROOT=/data/objects`。保留 Compose 中 backend 的 `object-data:/data` 挂载。
3. 后端必须能向文件目录写入，并能读取同一套 PostgreSQL 数据。重建容器时保留数据库卷和文件卷。多副本部署必须共享同一对象存储，不能各用不共享的本机目录。
4. 打开普通 Root 对话 `/chat/root-agent`，在输入框旁点击“添加文件或拖入此处”。解析在后端本地完成，无需配置 AILANG、GCP、OCR 或额外解析服务。
5. 等待每个文件显示“可用于分析”。文件会自动打开并勾选“参与分析”。检查文件名和预览，再输入问题，例如“比较这两个文件中的费用，列出差额并注明依据”。
6. 回答中应给出文件名和页码、行号、段落或工作表位置。文件显示可分析只证明解析完成；模型是否理解、计算和引用正确，仍需通过实际模型回答核对。

模型调用会把本轮勾选的文件文字交给配置的模型服务。选择模型服务时，应按部署方对文件数据的使用要求配置。

## 支持格式和读取范围

每个文件最多 **25 MiB**，每个会话最多打开 **10 个附件**。超过限制直接拒绝，不会只分析一部分而报告成功。

| 格式 | 提取内容与来源位置 | 明确限制 |
| --- | --- | --- |
| TXT | 非空行，标记原始行号 | UTF-8 或 GB18030；无法识别的编码需要转为 UTF-8 |
| Markdown | 文本行、标题，标记行号 | 图片链接不代表图片内容已读取 |
| CSV | 行列数据，标记行号；分块保留表头 | 不执行公式；不进行自动类型推断 |
| PDF | 文本层，标记页码 | 不做 OCR；纯扫描件失败；混合扫描页会写入未读取页提示；最多 1000 页 |
| DOCX | 正文及表格内文字，标记段落 | 不保留完整排版和表格结构；不读取图片、页眉页脚和嵌入对象 |
| XLSX | 各工作表单元格存储值，标记工作表、行和单元格地址 | 不重算公式、不解读图表和格式；无缓存值的公式需在 Excel 中计算并保存；日期可能表现为存储数值 |
| PPTX | 按幻灯片提取文字，标记幻灯片编号 | 不解读图片、图表和复杂视觉布局；不读取演讲者备注 |
| 图片、旧版 DOC/XLS/PPT、其他格式 | 拒绝上传 | 不启用无处理任务的“等待 AI 提取”流程；先转换为支持格式 |

加密、损坏、无可读内容的文件返回明确失败。Office 文件最多 10000 个 ZIP 条目，解压后总量最多 80 MiB；提取结果最多 20000 块，并受 100 万字符的序列化结果上限约束。需要时请拆分文件。

长文件首次进入模型的正文总预算为 32000 字符，按本轮附件数平分。输入明确标识“全文”或“前 N / 总字符数”的摘录范围。支持函数工具的模型可以用 `read_attached_document` 按偏移继续读取，每次最多 24000 字符。没有读完时，应报告分析范围，不能宣称全文已分析。使用 Gemini 内置代码执行器的模型不同时提供该函数工具，需要拆分长文件。

来源位置随文本进入模型，最终回答中的引用由模型生成；当前没有逐条结论的自动事实校验。复杂计算、完整表格还原和视觉理解不能仅凭文本解析成功推断。

## 选择、刷新与恢复

- **勾选**：该文件参与下一轮分析。取消勾选保留打开标签，但下一轮不再读取其正文。
- **移除标签**：从当前会话移除，不删除原文件。可从文件列表重新打开。
- **删除文件**：从文件列表删除原文件和元数据。其他会话中保留的标签会显示不可用，需移除。
- **同名上传**：每次生成独立文档和存储路径，不覆盖此前文件或其他会话正在使用的内容。
- **刷新/重启**：后端保存打开顺序和勾选状态；等待保存完成后可刷新或重建 backend。数据卷必须保留。
- **切换会话**：读取该会话自己的附件，不继承上一会话的文件。切换会中止尚未完成的前端上传，并忽略旧请求回调。
- **取消选择全部文件**：下一轮明确发送空列表。服务端不会从客户端旧 state 或用户级缓存补回已取消的附件。

已发送的附件分析及回答属于会话历史。取消选择控制后续附件读取，不抹除先前对话里已经出现的内容；需要没有旧讨论的新上下文时创建新会话。

附件列表加载、上传、解析和保存期间会阻止发送；失败时显示错误。可重试解析、重新上传，或取消选择/移除不可用标签后继续；未生成附件的上传失败需重试或移除记录。网络超时不保证服务器已撤销写入，可先刷新文件列表确认是否留下文件。

## 故障处理

| 现象 | 处理方式 |
| --- | --- |
| 上传按钮不可用或附件加载失败 | 检查登录状态、所属租户、会话所有权，以及后端接口错误；点击重试 |
| 上传进度完成，仍在解析 | 进度 100% 只表示字节已上传；等待解析结果，超时会显示可重试错误 |
| PDF 无文本层 | 用 OCR 工具在平台外转换为文本型 PDF/TXT，再上传 |
| XLSX 公式无缓存结果 | 在 Excel 中计算、保存后上传，或导出 CSV |
| 解析失败 | 查看具体原因，尝试重新导出；“重试解析”复用已存文件，不必再上传同名副本 |
| 旧文件显示需重新解析 | 旧的 `pending_ai_extraction` 没有本地工作者，不会自动完成；重新解析支持格式或重新上传 |
| 模型说没有收到文件 | 检查标签是否勾选、解析状态和保存状态；检查本轮请求是否携带文档 ID；检查真实 Provider 回答与后端错误 |
| 重启后丢失附件 | 核对数据库连接、Session 后端和持久卷是否仍是原来的实例；不要通过创建新数据库掩盖数据问题 |
| 无权限/不存在 | 文件与会话必须同时属于当前账号和稳定租户；不要修改 UID 或 tenantId 绕过检查 |

## 服务端约定

文件列表和预览统一使用带身份认证的 REST 接口，不再直接订阅 Firestore。接口由当前登录身份确定 UID 和租户，客户端不能自行指定其他用户。

| 接口 | 作用 |
| --- | --- |
| `GET /api/documents/capabilities` | 格式与大小、数量限制 |
| `POST /api/documents/upload` | multipart：`file`、可选 `folder_id` 和 `skill_id`；返回终态和解析错误 |
| `GET /api/documents/{id}` | 读取已授权的文档与解析结果 |
| `POST /api/documents/{id}/reparse` | 从原对象重新解析；替换旧内容和摘要，清空旧块编辑 |
| `GET /api/documents/{id}/download` | 认证下载，不向浏览器暴露本机对象路径 |
| `GET/PUT /api/sessions/{id}/documents` | 保存/恢复有序的 `{id, included}` 附件标签；限当前租户的会话所有者 |
| `POST /api/agent/stream` | 每轮在 `forwardedProps.document_ids` 明确发送选择；空列表表示无附件 |

服务端在进入流式模型运行前检查所有附件的用户、租户、删除状态和可读内容；任一不可用返回 `409 / DOCUMENT_UNAVAILABLE`。模型输入从当前文档记录构造，原生文档工具再次检查本轮选择，不通过 Artifact 缓存恢复附件。

独立配置的 Root 知识来源属于[知识检索](configuration-guide.md#81-知识来源)，不由对话标签的勾选状态控制。

| 验收层次 | 当前证据/要求 |

| 本地解析 | 使用真实 PDF、DOCX、XLSX、PPTX 文件夹具及 TXT/Markdown/CSV 测试；覆盖空文件、损坏文件和限制 |
| 输入契约 | 实际上传、本地对象存储、Root/AG-UI/ADK 到模型输入探针，检查多文件、取消选择、旧 state 不恢复、失败前阻断和相同 UID 跨租户拒绝；**探针不是外部真实模型** |
| 前端状态 | 组件/Hook 测试检查上传进度、重试、并发、同名文件、会话切换、快速添加后清空、保存失败和解析状态刷新 |
| PostgreSQL | 集成测试重建 repository 后恢复附件顺序/选择，并验证相同 UID 不同租户的拒绝；需要带数据库运行，不以 memory 测试代替 |
| 浏览器 | `frontend/e2e/chat-files-live.spec.js` 使用 Chromium、真实上传、PostgreSQL 和本地卷，验证新对话、五种文件、取消勾选、刷新、失败和会话切换 |

| 目标安装升级 | 历史文件归属、旧 Session/Memory、备份恢复与回滚未因这些新环境测试而自动证明，继续按 Issue #9 验收 |

开发者可运行后端 `tests/unit/test_native_document_parsing.py`、`tests/api_tests/test_documents_reach_agent_e2e.py`、`tests/tool_tests/test_document_injector.py`；PostgreSQL 使用 `tests/integration/test_postgres_document_metadata.py`。常规浏览器用例接入 Model provider gate，真实模型用例接入 Real Provider acceptance。应核对对应 PR 的具体 check/run 结果，不能将已添加测试当作已通过。

## 已有部署升级前

本次删除用户级附件缓存和基于旧 state 的自动补回，不增加旧附件状态的兼容读取。历史 session 仅有 `documentIds` 时不会自动推断其打开顺序和勾选状态；需要在目标安装上确认历史归属后重新选择，或在维护窗口执行审核过的数据迁移。

升级前备份 PostgreSQL、对象卷、Artifact 卷及配置；在隔离副本核对历史 `userId`、`tenantId`、`storagePath`、解析内容和 `documentTabs`。用两个同 UID、不同租户的账号检查预览、下载、会话恢复、模型输入和工具分页均不可串读。再用旧版本和一致数据快照完成回滚演练。未经这些目标环境验收，不能据此承诺已有部署可无风险升级。
