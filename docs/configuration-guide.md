# 配置流程

平台只有一个面向用户的 Agent。管理员配置公共能力；用户在个人设置中补充自己的 Skill 和信息。

## 1. 部署与登录

按 [自托管部署](../SELFHOST.md)配置 PostgreSQL、JWT 和持久化对象卷。首次启动使用 `SELFHOST_ADMIN_EMAIL`、`SELFHOST_ADMIN_PASSWORD` 创建管理员。普通用户在管理控制台的“用户管理”中创建，不需要组织目录或权限组。

登录后直接进入 `/chat/root-agent` 的 AI 任务对话，不自动恢复或执行最近任务。`/workspace` 保留为任务概览辅助入口。`/sessions` 提供当前用户全部历史的服务端搜索与分页恢复，支持标题、会话编号和更新时间范围。导航登录入口复用密码 / OIDC / Google 的现有登录控件。管理员从 `/admin` 查看真实就绪清单及资源入口；配置完成与目标账号实际可用是两次独立确认。

## 2. 模型

在“模型服务”中添加服务地址及密钥引用，注册模型，完成普通生成和工具调用测试，再应用到 Root Agent。模型、回退链和驻留策略由服务端决定，个人 Skill 不改变这些设置。

数据库动态模型切换在专用应用接口和通用 Root 配置保存入口都要求当前配置及凭证指纹下、24 小时内的普通生成与工具调用测试通过。同一模型的其他字段保存、配置文件模型与既有别名不套用此新增切换门禁；测试过期也不会因此新增运行时停服规则。就绪清单的绑定数量不等于授权或可用，模型策略允许也不等于双测试通过。

OpenAI 兼容服务配置见 [接入说明](selfhost-openai-compatible.md)。密钥只通过部署环境或服务端密钥引用配置，不写入 Skill、个人信息或日志。

## 3. Agent 公共能力

打开“Root Agent 设置”：

- **公共 Skill**：绑定可供用户使用的 Skill 内容；访问共享资源仍执行资源 ACL。
- **工具**：绑定原生工具；撤销绑定后，已有调用也重新检查当前配置。
- **MCP**：先在“MCP 服务”注册、检测及发现服务器，再绑定到 Agent。
- **知识**：从自己上传的已解析文件创建来源，选择私有或公共共享，再绑定到 Agent。
- **交互**：配置 A2UI、操作触发、语音和欢迎语。

Skill 提供指令、参考资料和资产。它不能自行增加模型、原生工具、MCP 连接或授权。

需要在聊天中显示业务计划时,在“工具”中绑定 **任务计划与进度**。助手可报告公开步骤及待执行、执行中、待补充、完成、失败、取消状态,随后更新同一张卡片。计划状态为助手最近一次报告,刷新只恢复已保存记录,不会自动继续任务。该工具由固定的 A2UI 映射展示,不依赖允许模型直接生成 UI 的开关;确认操作仍使用原有表单。详见 [计划实现契约](design/ux-redesign/TASK_PLAN_IMPLEMENTATION.md)。

## 4. 用户专有配置

账号菜单 → **个人 Skill 与信息**：

1. 创建属于自己的 Skill。
2. 在个人设置中勾选要使用的 Skill。
3. 填写需要助手使用的个人信息和偏好，保存。

也可在 `/skills` 能力中心对本人拥有的 Skill 点击“为我启用”。页面在点击时重读个人配置，合并原绑定并保留最新个人信息，保存确认后再由服务端确认可调用状态。“开始使用”只进入对话，不自动发送。共享资源可见不等于可个人绑定；状态未知时不可开始，可重试。Studio 未开启时不显示新建、编辑或创建副本入口；新建保存成功后进入实体 ID 的编辑地址，后续保存更新同一实体。

运行时可用 Skill 是 Agent 公共绑定与当前用户个人绑定的合并结果。个人绑定必须由该用户拥有，不能填写别人的私有 Skill ID。个人信息只组合到该用户的运行配置，并参与 Agent 缓存标识。

管理员可在“用户管理 → 编辑个人配置”中编辑账号的个人绑定与信息，包括管理员自身。个人配置与账号停用、密码重置等账号安全操作分开校验。当前账号和管理员账号不能被停用。

## 5. 文件、会话和记忆

用户 ID 只来自已验证的登录身份。附件上传、预览、下载、重新解析、删除、进入模型输入和工具分页读取都检查用户归属。新会话默认私有；显式共享会话可按 ACL 读取，修改仍要求所有者。

会话搜索只读取当前用户未归档、非预创建会话的索引元数据，不搜索聊天正文。搜索条件按提交生效，日期按浏览器本地整天计算；更改条件或账号会清除旧页。翻页失败可重试读取，打开原会话不会主动调用模型。接口、存储后端性能边界和回滚见 [会话搜索实现说明](design/ux-redesign/SESSION_SEARCH_IMPLEMENTATION.md)。

ADK Session 的 app 状态、Memory、Artifact 和本地/S3/GCS 对象均按用户隔离。更换用户不能复用原用户的会话状态或文件。文件分析操作见 [聊天附件](chat-file-analysis.md)。附件初始化、保存或解析失败时仍可编辑草稿，但发送和其他会触发模型的交互仍受附件可读性校验；不会静默丢弃附件后发送纯文字。引用导入失败提供可见错误和重试。

`/results` 先选择可访问会话，再通过 `GET /api/sessions/{session_id}/results` 读取 metadata-only 摘要；只展示持久化 A2UI 交互成果，不包含上传附件、知识来源或普通聊天文本。入口不遍历所有会话消息，也不开放管理员原生 Artifact 接口。每个会话最多返回 100 条去重成果，截断、不完整和会话状态不可用均单独提示。返回原对话不重跑工具；当前不提供指定成果标签的深链，也不是全量文件搜索。

### 对话中的执行与成果

真实工具调用在消息流的“执行活动”卡中更新，普通聊天与 A2UI 操作使用同一条 AG-UI 运行流。卡片只显示已收到的阶段和工具返回；没有结构化业务计划时不会虚构计划或百分比。Run 结束与业务成功不同；刷新后的记录标记为历史活动，不推断历史 Run 已完成。停止只取消当前流，不撤销已执行操作，也不自动重放工具。

A2UI 交互按后端配置在聊天内渲染；已处理的确认卡禁用鼠标及键盘再次提交，普通可复用 A2UI 仍可继续操作。受控动作仍由后端校验身份、会话和 Root 配置。成果卡读取已存在的 Surface 元数据；“查看预览”可展开辅助工作区，不新增文件下载或 PDF / DOCX 导出能力。

## 6. 验收

用两个不同用户执行：

1. 询问有哪些 Skill，确认公共绑定可见，个人绑定仅本人可见。
2. 实际加载 Skill、调用原生工具和 MCP。
3. 更改个人信息后重新调用，确认立即生效。
4. 撤销 Skill、工具或 MCP 后，用原令牌复验访问被拒绝。
5. 尝试读取另一用户的附件、Session、Memory 和 Artifact，确认被拒绝。
6. 提交 A2UI 表单、刷新页面并恢复状态。
7. 从工作台和历史跨 Skill 恢复同一会话，确认会话 ID、消息和附件连续；附件出错时草稿可写、不可发送。
8. 从成果页选择来源会话、读取摘要并回原对话；核对跨用户拒绝、错误重试、状态缺失和截断提示。

以上为目标部署的人工验收要求，不表示已在当前部署执行。

[真实调用验收](real-provider-acceptance.md)需要运行目标服务，单元测试不代替真实 Provider 证据。

## 7. 旧部署升级

本次升级直接丢弃旧组织数据，不转换归属，不提供数据迁移或回滚工具。后端启动时执行 `002_user_owned_reset.sql`，删除旧目录、权限组、专属 MCP、组织归属内容及对应 ADK namespace；保留账号凭据和公共平台配置，并移除废弃字段。

新数据直接按用户 ID 写入。旧对象卷或远程桶中已失去元数据引用的二进制文件不会被复制；物理删除需在拥有该存储的部署中执行。本仓库修改不代表已访问或清理任何运行中的服务器。
